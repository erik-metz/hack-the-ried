# Private on-air delta update: RAK3112-003

Verified on 2026-11-07 with the USB-powered RAK3112-003 and the RAK2287 in
`kamue-lora-pi`. This is the project's experimental FPort-43 protocol, not a
TS004/TS005 interoperability or multicast test.

## Result

The device initially ran firmware 1/value 111 from `ota_0`. ChirpStack sent a
delta manifest and four changed blocks (indices 1, 342, 344, 3005). The receiver
reported all 3006 image blocks present, verified the complete target SHA-256,
selected `ota_1` and rebooted. Serial output then reported firmware 2/value 222,
`OTA running=ota_1`, a restored LoRaWAN session, and a value-222 uplink. Independently,
the Pi sender observed that actual uplink via ChirpStack MQTT and reported:

```text
Status {"state": 3, "session": 1307009673, "received": 3006, "total": 3006, "missing": []}
VERIFIED: firmware 2, value 222 received from 70B3D57ED0079D88
```

Both images are 384768 bytes. The exact common binaries are kept locally under
the ignored `hardware/sensor-node/rak3112/fuota/build/rak3112-003/chirpstack/`:

| Image | SHA-256 |
| --- | --- |
| `1/dummy.ino.bin` | `5fd7d37c6f78a83c340d6413f75483748c2ebf8fa1ab0325dea718e2b958c305` |
| `2/dummy.ino.bin` | `9c54aeba58ff0f46d39f241528a7870b0a2176383d8049fd2cb6dc615731efd6` |

Firmware source: `aec18305c89ff2fbc2a7c0da07f61f1bd617dfb9`. Build configuration:
ESP32 core 3.3.11, RadioLib 7.7.1, ESP32-S3 hardware CDC, 16 MiB flash,
OPI PSRAM, private network 2. Device identity and RadioLib security counters
remained in NVS across the firmware replacement. Use this exact A binary for
the next board; rebuilding A can change its base hash.

## Gateway and recovery

The gateway base image was pinned to
`ghcr.io/erik-metz/hack-the-ried-gateway:sha-d5008847a085a3f2f83958072abc16bc23052f9d`,
with the v2 router bind-mounted from source `5e500b4`.
After completion, Docker health was `healthy`; `radio_ready`, `station_connected`,
`lns_connected`, and a fresh `private_lns_connected` were all true. This proves
concurrent LNS connections; it does not establish a new production TTN uplink
after switching this test device to the private network.

Watchtower is stopped for the experiment. The host guardian remains running
and accepted the new healthy image. The verified original TTN image is also
retained as `kamue-gateway:fuota-verified-ttn-baseline`. The original deployment
manifest, credentials and state remain under `/home/alpha/hack-the-ried/gateway`.
Use the README rollback procedure to return to the original single-LNS setup.

The first attempt exposed two real integration issues: Gateway Bridge omits
zero-valued radio fields and represents unused DRs differently from TTS; and
patching a cloned NOR-flash sector requires erase/read-modify-write. Tests now
cover both. Before the successful retry, the guardian automatically restored
the old TTN deployment after repeated candidate restarts. It was rearmed with
the known-good image retained. The first complete transfer failed its target
hash and correctly retained firmware 1; no invalid image was selected.

Private registrations were transported as authenticated ciphertext to a key
generated on the Pi. Device credentials were not logged or committed. The
common A/B binaries were scanned for the selected raw and derived device keys.
